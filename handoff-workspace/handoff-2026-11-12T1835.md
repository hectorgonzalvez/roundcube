## Decisions preses i per què

- **Pila `cap` en lloc de .NET + Oracle + Vue**: el generador la va suposar perquè la carpeta era
  buida; el projecte són plugins PHP. Amb `cap` queden només les regles comunes i cap de les de
  .NET/Oracle/Vue, que haurien guiat malament tots els skills.
- **Les quatre regles pròpies** (no tocar el nucli, només API pública de plugins, base 1.7,
  cada plugin desactivable sol): l'objectiu declarat és rebre les actualitzacions de seguretat i
  l'estabilitat de Roundcube; les quatre fan que actualitzar-lo siga substituir-lo i prou.
- **CI a Azure DevOps**: és on correrà; checks bloquejants des del principi (projecte nou).
- **Permisos**: `allow` adaptat a `composer install`, `vendor/bin/phpunit`,
  `vendor/bin/php-cs-fixer`; `composer require` en `ask`. Esta sessió anava en auto-mode, on
  `ask` no s'aplica: només hi actua el `deny`.
- **Proposta de descobriment a nivell de projecte**, no plugin a plugin: el document de proposta
  (https://claude.ai/artifact/JLEWTMCwC3FuHumcbrg4Tv) és un catàleg del que es pot fer, no del
  problema que tenen els usuaris de la UA.
- **Recomanació, sense decidir**: un monorepo amb una carpeta per plugin (un kit, un PRD, una CI).
